# Session Harbor 产品需求

状态：Draft · 日期：2026-11-02 · 实现状态：基础原型开发中；Desktop 核心目标未实现、M0 未执行

## 问题与用户

用户拥有自己的多个 Claude Pro 账号，主要在 Windows 上使用 Claude Desktop 的 **Code 编程标签页**。账号切换会打断编程工作，用户希望知道当前实际使用哪个账号、了解可获得的用量信息，并在切换后直接接着原对话工作，而不必重新解释项目背景。

目标用户为个人开发者；首版仅处理用户自己有权使用的账号。Desktop Chat 历史迁移与单纯 CLI 会话恢复均不属于本需求。

## 目标与非目标

1. 核验 Desktop 的实际账号身份，避免“界面显示 B、实际仍使用 A”。
2. 支持用户主动发起切换，并在切换前处理在途工具任务和子进程。
3. 在原项目、原 worktree 与原会话中恢复编程上下文；这是核心目标，不得由“能打开旧记录”替代。
4. 用量必须标注来源、所属账号、观测时间和可用状态；来源不明或失败时显示 unknown。
5. 切换失败时保留清晰恢复路径，不破坏原工作区。

非目标：多供应商切换、第三方 API key 管理、Desktop Chat 迁移、自动轮换绕过额度、账号共享服务、官方客户端改造、保证账号不受限、跨机器同步、首版 macOS/Linux 支持。

## 用户故事与需求

| ID | 用户故事 | 验收要求 |
| --- | --- | --- |
| R1 | 我想区分自己的多个账号 | 本地别名与核验身份分离；未核验、已核验、过期、不可用均能表达；不得仅凭别名确认身份 |
| R2 | 我想从 A 手动切换至 B | 切换由用户发起；先显示受影响项目与在途任务；不在任务状态未知时静默继续；通过官方支持且经验证的路径完成登录 |
| R3 | 我想知道切换真的生效 | 在 Desktop 内获得可复核的 B 身份证据；CLI 状态只能作为辅助记录；证据不足时不得标记成功 |
| R4 | 我想接着原编程对话工作 | Desktop 中定位原会话，确认项目/worktree 一致；能回答仅存在于原对话的测试上下文，并在测试项目内继续无害任务；保留可复查证据 |
| R5 | 我想了解剩余额度 | 展示经验证来源的原始口径、账号、观测时间和重置时间（若提供）；未知不显示为 0；本地 token 估算不得冒充订阅剩余额度 |
| R6 | 切换失败后我想恢复工作 | 明确当前身份和失败阶段；允许取消或通过官方登录恢复 A；恢复后核验项目与会话；失败则停留在需人工处理状态，不循环切换 |
| R7 | 我不希望账号隐私进入仓库或日志 | 不收密码；最少化保存非敏感元数据；日志不含令牌、Cookie、完整对话或敏感路径；未来秘密存储须单独评审 |

## 成功标准

当前原型实现本地账号别名增删改、只读安装候选检测、unknown 用量展示和 blocked/cancelled 预检历史。账号档案不代表已登录，预检不执行账号切换。浏览器预览为纯内存数据，原生路径使用 Rust/SQLite；分别验证，见 [构建与测试记录](validation/prototype-build.md)。这些工作只覆盖基础体验，不关闭 R1–R7 的完整验收。

M0 必须完成 [人工验证计划](validation/desktop-code-handoff.md)，形成可复现的 Desktop 身份 B、原会话接续、工作区一致和恢复 A 的证据链。任何环节无法验证，均不能宣告核心目标完成。

[ASSUMED] 在同一组受支持版本下，A→B 与 B→A 各连续成功 3 次，作为进入 Windows MVP 的最低稳定性样本；这不是普遍兼容性承诺。

[VERIFY WITH USER] MVP 的切换耗时目标、允许的人工步骤、成功率样本量与可接受的客户端版本范围尚未确定。没有当前操作时长或失败率基线，不设虚构提升百分比。

## 体验与异常规则

切换顺序为“选择目标 → 检查工作状态 → 等待或由用户停止在途任务 → 官方登录流程 → 核验 Desktop 身份 → 核验原会话 → 继续”。取消、超时、网络不可用、身份不一致与会话不可见均应显示具体状态及恢复入口。

对于订阅用量，区分 `known`、`stale`、`unknown` 和 `unavailable`；旧值只能连同时间戳明确展示为旧值。遇到限流时尊重来源允许的刷新频率，停止密集重试并提示用户，不触发账号轮换。

## 依赖与未知

- [待技术验证] Desktop Code 是否支持跨本人账号接续同一会话，以及可依赖的官方入口；目前无实测证据。
- [待技术验证] Desktop 的身份核验方式、会话与账号绑定关系、worktree 生命周期和登录后恢复行为。
- [待技术验证] 订阅用量是否存在适合本项目且获准使用的数据来源；不可用时显示 unknown 状态。
- [待技术验证] Windows 最低版本、Desktop 兼容版本、安装与签名方式。
- MVP 不设独立 HTTP 后端；技术栈为 Rust + Tauri 2 + React + TypeScript + SQLite，凭据仍由官方客户端管理，SQLite 不保存 token。
- [ASSUMED] 首版为本机单用户应用且不设遥测；后续变更需独立评审。

若只能新建对话并复制摘要，应单独命名为“上下文交接”，明确不等同于原会话接续，并先重新评审产品范围。不能用该降级方式关闭 R4。

## 发布门槛

技术栈已确定。基础原型可与 M0 调研并行；必须通过 M0 后，才能依据证据确定 Desktop 集成方案并验收 Windows MVP。核心路径、失败恢复和隐私边界均需证据；macOS 需要独立验证。详细顺序见 [路线图](ROADMAP.md)。
