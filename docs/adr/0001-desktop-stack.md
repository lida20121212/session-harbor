# ADR 0001：桌面技术栈选择

状态：**Proposed（尚未批准）** · 日期：2026-11-02

## 背景

Session Harbor 面向 Claude Desktop Code，Windows 优先、后续 macOS。当前只建立文档仓库；没有应用代码、锁文件或可运行包。M0 首先验证官方客户端的身份和会话接续能力，框架选择不能解决该依赖。

## 候选方案

| 方案 | 适用路线 | 收益 | 成本与待验证项 |
| --- | --- | --- | --- |
| Go + Wails + Vue 3 / TypeScript | 从零开发独立应用，当前推荐 | 模块边界可按本产品需求设计；Go 负责本地协调，Vue 负责界面 | [VERIFY WITH USER] 维护者熟悉度；[待技术验证] Windows 打包/签名、系统集成与未来 macOS 适配需原型评估 |
| Rust + Tauri + React / TypeScript | 决定借用 cc-switch 代码时优先评估 | 接近参考项目现有栈，减少移植语言与 UI 框架的转换 | 借入供应商/CLI 功能可能增加无关复杂度；仍需独立验证 Desktop Pro 身份与会话；保留 MIT 版权及许可 |

## 建议

在从零开发前提下推荐 Go + Wails + Vue 3 / TypeScript；若后续决定大量复用 cc-switch 实现，则重新比较 Rust + Tauri + React 的总体成本。此建议尚未批准，不锁定版本，不据此建立空壳依赖或编造构建指令。

## 决策前需要的证据

1. M0 确认的 Desktop 集成方式，以及该方式是否需要平台专用能力。
2. [VERIFY WITH USER] 实际维护者技能、可投入时间和是否计划复用第三方代码。
3. 最小平台原型的启动、打包、签名和系统集成结果；原型不能被称为已具备会话接续功能。

## 后果

当前保持文档与接口边界层面的可逆决策。若选择复用路线，需记录具体上游提交、复制文件、许可与本地改动；当前研究的 `main` 分支证据不等于已选择的可复用版本。
