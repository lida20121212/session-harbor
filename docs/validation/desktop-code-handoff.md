## 目的与前提

验证用户自己的 Pro 账号 A 切到 B 后，Claude Desktop 的 **Code** 标签页是否能继续同一项目、同一 worktree 的原对话，并能失败恢复 A。CLI 的认证、目录和会话只可作为辅助信息，不能替代 Desktop 证据。

人工执行人需准备：自己的两个可用账号、Windows 与 Desktop 版本记录、无秘密的临时 Git 项目、可丢弃的测试文件及本地证据目录。登录由执行人通过官方流程完成；不向本项目提供密码、令牌、Cookie、认证回调或完整私密对话。

[待技术验证] Desktop 可支持的身份观测入口、会话标识与跨账号恢复入口尚未知。若无法找到官方支持且可复核的操作入口，记录阻塞，不通过修改官方索引、凭据文件或复用令牌接口来绕过。

## 执行步骤

1. **建立基线**：记录日期、时区、Windows/Desktop 版本、项目与 worktree 的脱敏引用。通过 Desktop 可见且可复核的账号信息确认 A。若仅能看到 CLI 身份，停止身份验证并记录阻塞。
2. **创建原会话**：在 Code 标签页的临时项目创建对话，输入只存在于对话中的随机测试短语，并约定一个简单的下一步任务。不要把短语写入项目文件。记录会话可用标识、标题或其他可复核定位证据。
3. **检查工作上下文**：在临时项目创建一个未提交的无害测试文件，记录工作区状态。确认当前项目根目录及实际 worktree，而非仅比较窗口标题。只在本地保留真实路径，公开证据使用代号。
4. **处理在途任务**：分别检查模型回复、工具调用、终端和仍可能写文件的子进程。正常路径等待完成；取消路径由执行人停止可控测试任务并确认子进程结束。状态不明时停止切换，不强制终止未知进程。
5. **切换账号**：仅通过可用的官方 Desktop 登录/退出流程由 A 切到 B，记录具体步骤、耗时、重启要求及异常。没有合适路径则记录阻塞。
6. **核验实际身份**：在 Desktop 内确认 B，记录脱敏证据。不得依据 Session Harbor 别名、CLI `auth status`、浏览器登录状态或登录提示“成功”就判定 Desktop 已切换。若只有间接证据，结果为无法验证。
7. **恢复原会话**：在 Desktop Code 通过官方入口定位原会话；核对项目/worktree 和未提交文件状态。询问前述随机短语且不重新提供短语，继续约定的无害任务，检查工具实际作用于原 worktree。记录原历史可见性、上下文回答、会话定位和新响应。仅看到旧消息或新建对话后粘贴摘要不算通过。
8. **核验用量**：检查有官方依据且适用的数据来源，记录账号、口径、观测时间和重置时间（若提供）。无法获得订阅剩余额度则记录 unknown，不能填 0 或用本地 token 数替代。不要为完成此项读取令牌调用私有接口。
9. **恢复 A**：通过官方流程返回 A，再核验 Desktop 身份、项目/worktree、原会话和未提交文件。取消 B 登录或用无害方式模拟网络不可用时，检查失败后是否能按同样路径恢复；不得人为损坏凭据或会话数据。
10. **重复与归档**：[ASSUMED] 正常路径 A→B、B→A 各重复 3 次。按具体版本归档通过/失败/阻塞，不把单次偶然成功推广到其他版本。
