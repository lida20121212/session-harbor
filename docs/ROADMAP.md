# 路线图

日期：2026-11-02 · 基础原型开发中，M0–M3 尚未完成，无发布日期承诺。

技术栈已确定为 Rust + Tauri 2 + React + TypeScript + SQLite，详见 [技术栈决策](adr/0001-desktop-stack.md)。栈选择不代表 Desktop 集成方案已验证。

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| 基础原型：与 M0 并行 | 账号档案、SQLite、受限 IPC、安装候选检测、未知用量、阻塞预检历史 | 按前端、存储、原生构建分别完成检查；不以此替代 Desktop 核心验收 |
| M0：Desktop Code 可行性 | 按版本记录的人工证据、支持方式与限制、Go/No-Go 结论 | Desktop 身份确为 B；同一项目/worktree 与原会话上下文可接续；任务停止/完成可确认；失败后能恢复 A；用量来源可用性有明确结论 |
| M1：Windows MVP | 采用已选技术栈的最小应用、手动账号切换协调、会话核验、带来源的用量或 unknown、脱敏诊断 | M0 通过；安全边界评审；正常/取消/失败恢复路径均经实测；范围明确且无“防封”承诺 |
| M2：Windows 公开预览 | 安装与卸载、发布签名方案、兼容版本表、已知限制、贡献说明 | 安装及升级验证；不泄露本地秘密；构建可复现程度与限制如实记录 |
| M3：macOS | 平台适配与独立验证证据 | 在 macOS 重新验证身份、会话、worktree、子进程及恢复；不能沿用 Windows 结论 |

## M0 的决策门槛

执行 [验证计划](validation/desktop-code-handoff.md)，先确认官方允许且可复核的路径，再决定集成实现。当前所有 M0 人工测试均为 `NOT RUN`；基础代码检查另见 [原型验证记录](validation/prototype-build.md)。

- **Go**：核心 Desktop 路径和恢复得到证据，且存在可接受的集成方式。用量若无可用来源，只能明确标记 unknown，并在 MVP 范围评审中记录限制。
- **No-Go / 待研究**：身份无法核验、原会话无法跨账号恢复、工作区不可保持、在途任务状态不可确定，或方案依赖未经批准的凭据操作。
- **范围重议**：只有 CLI 可成功、只能新建对话传递摘要，或只能查看旧历史时，保留这些事实，但不能替代 M0 成功；先征得产品范围变更决定。

技术栈已确定，基础源码和依赖锁文件已建立。在 M0 结论前不承诺自动化切换，也不选定新的凭据操作方案。账号档案 CRUD 与阻塞预检可以独立推进；即使这些检查全部通过，也不能宣告 M0 或 Windows MVP 完成。此次安排见 [实施决策](decisions/0002-prototype-implementation.md)。
